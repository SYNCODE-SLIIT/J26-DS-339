## 6 November decision for the short-hum pilot

The primary input is a 5–15-second melodic hum with multiple short notes.
Guided takes provide a musical target when the singer confirms the intended
register and phrasing. Free hums test whether BPDR preserves the participant's
idea. The 37-trial held-voice review in Section 2 is separate historical
development work.

Before collection, freeze the guide audio and note timing, include short notes
in all three guided phrases, and document permitted registers and intentional
expressive movement. Record clip lengths and note durations so coverage can
be reported. Keep out-of-scope attempts and retries in the feasibility count.

Give both reviewers the full clip, the aligned guide where available, and two
versions in independently randomized order at identical playback gain.
Collect preference, preservation judgments and timestamped artifacts. Ask
the participant separately whether the output still expresses their idea.
Use identity controls and retain withholds in the attempt count. Label
experimental previews separately from audio the system actually delivers.

Compare the frozen Transformer, ExtraTrees and original audio on the same
eligible clips and reference spans. Report pitch error and improvement on
delivered WAVs where a reliable reference exists, coverage over all attempts,
changes to protected audio, audible harm and downstream note agreement where
independent note labels exist. Break out guided and free hums and show counts
by participant. Freeze the evaluation rules before confirmation. The current
short-note experiments failed declared gates, so promotion remains pending.

## 1. What this plan needs to establish

Answer two different questions:

1. Can an existing recording serve as a trustworthy controlled-recovery
   reference, and does a prepared version preserve its musical idea/expression?
2. Does a locked system help on unfamiliar people and realistic vocal ideas,
   including material it should keep unchanged or request again?

Automatic sample/pitch checks, user confirmation and independent musical review
are different evidence. A good numerical score cannot fill in a missing rating.
Musical plausibility does not prove the performer's intended pitch.

The current Transformer reference remains unqualified for a usable-accuracy
claim. The existing demo selection stays unchanged. Collection and review will
support evaluation and reference suitability; they do not certify the model.

## 2. First: two independent musical reviewers

Recruit two adults with relevant singing, instrumental or music-teaching
experience. Record that experience and any relationship to the project. They
review independently before any discussion. The model developer may prepare
the packet and hold its answer key, but must not fill either independent rating.

### Reference-suitability review

Both reviewers assess all50 existing original recordings. Preserve the
recording/source IDs and current singer/source partitions.

For each original, record:

- Suitable as a controlled-recovery reference: yes / no / unsure.
- Stable regions usable for this declared held-voice task, using time ranges.
- Any intentional vibrato, glide, onset or expressive movement to preserve.
- Audible technical problems and reasons for no/unsure.

Approval means suitability for this specified experiment, not perfect intonation
or a complete intended-note annotation. Two actual yes ratings, applicable
source permission and passing technical audits are needed before a source can
be considered for a newly declared research-training set. Development/final
source roles still prohibit fitting even if a reference is approved. Existing
engineering fits do not become retrospectively research-approved.

### Blind repair review

Use the23 currently verified reference-Transformer repair outputs, without
selecting only the best-sounding ones. These cover6 source groups in the saved
results, rather than every attempted singer. Add10 bit-identical identity
controls, one per attempted singer group, and4 repeated trials selected with
fixed seed339 before ratings. This gives37 trials per reviewer.

For a repair trial, provide the unshifted performance as a reference and two
neutrally named versions X/Y: the controlled detuned input and verified output.
Randomize X/Y and trial order independently for each reviewer. For identity
controls, X/Y contain the same working original. Repeats reuse an existing
trial; they are not new independent cases.

The owner-only key holds model names, injected shifts, source labels, hashes
and repeat/control status. Reviewer filenames must be neutral; names such as
`detuned_-30.wav` would reveal the condition. Keep all audio at the same playback
gain, without per-version normalization or extra processing. Provide the full
context, not only the corrected region, so unintended changes can be heard.

Record separately:

| Question | Allowed answer |
|---|---|
| Which version is closer to the reference? | X / Y / no meaningful difference / unsure |
| Does each version preserve tune and expression? | yes / no / unsure, separately for X and Y |
| Is there a newly audible problem? | yes / no / unsure, with a time range and description |
| Is the output suitable to pass onward for this scope? | yes / no / unsure |

Do not force a preference when changes are too small to judge. A listener cannot
authorize a candidate that fails a technical check. Rolled-back/unverified
renders must not be presented as accepted repairs.

Plan several short sessions with breaks: reference review can be split into
two25-recording batches and pair review into19/18 trials. Allow replay. Actual
time depends on clip length and reviewer comfort; do not promise a fixed total.

Preserve both original ratings. A disagreement stays visible, with an optional
separately recorded adjudication; it does not become two agreeing reviews.
Unsure remains unassessed. Repeat/control responses describe consistency and
possible bias; four repeats alone cannot establish or invalidate expertise.

This round is retrospective development review. Preference among verified
previews is conditional on those previews existing. Keep all200 attempts,
108 scoreable cases,92 construction exclusions and withholds in the separate
engineering readout. Do not turn23 selected output reviews into overall success
on200 attempts or fresh validation of a repeatedly inspected cohort.

## 3. Second: an eight-adult feasibility pilot

Retain the master plan's estimate of8 adults x6 phrases =48 planned recordings.
This is a feasibility target, not completed recruitment or a statistical power
calculation. Recruiting adults only is the proposed initial scope. Do not
represent professional source-category labels as verified demographics.

Each participant records3 guided phrases and3 free-hummed/sung ideas:

| Task | Purpose | Reference evidence |
|---|---|---|
| G01: simple stepped phrase with short notes | Measure short-note recovery and preservation | Approved guide and agreed intended register |
| G02: phrase with changes and a pause | Observe boundaries and appropriate preservation | Approved guide, independent alignment/annotation |
| G03: phrase with an optional expressive movement | Test preservation of intentional expression | Guide plus participant's explanation of intended movement |
| F01/F02/F03: participant-created short ideas | Observe realistic unaccompanied input | Participant explanation and preservation judgment; intended pitch may remain unknown |

Approve/source the three guide stimuli before recording; this plan does not
invent their notes or claim the stimuli are already prepared. Explain reference
register and any intended transposition before each guided take. An intentional
whole-phrase transposition must not be labelled an error automatically.

Aim for5–15-second clips within the existing20-second limit. Record normal,
comfortable singing/humming; do not ask people to manufacture bad intonation or
strain. A held region is useful when it belongs to the idea, not a reason to
change someone's intended rhythm or expression. Stop or offer breaks on request.

Use an existing microphone/phone capable of WAV/FLAC, one unaccompanied voice,
and a consistent setup in a quiet room. Participants can hear a guide first;
stop external playback while recording so it does not leak into the microphone.
Keep native source files unchanged. The existing pipeline creates the mono
22,050Hz PCM24 working copy and records source hashes and any time mapping.

For a technical failure, retain the attempt and its reason. A single optional
retry may be offered; keep both IDs and the relationship between them. A retry
does not silently erase a failure or create another independent participant.
Keep the48 planned phrase slots distinct from actual attempts, retries and
usable recordings. Do not count a planned slot as a collected example.

After a take, ask the participant whether it represents the intended idea and
which movements were intentional or uncertain. Free humming without a reliable
reference must retain `intended_pitch_known=false`; do not create numerical
pitch targets from the model's own output or reviewer preference.

## 4. Reserve people before analysing recordings

Propose4 development participants and4 untouched confirmation participants.
Allocate from consented metadata before audio analysis using a documented,
deterministic rule (seed339), considering experience and available source/voice
categories. Do not choose the final group after hearing their recordings.

Every phrase, retry, crop and intervention from a person stays in that person's
partition. The initial pilot is evaluation-only: no participant enters current
gradient fitting. If more training data is needed, declare a separate training
cohort or explicitly training-permitted, reviewed public sources. Do not move
confirmation participants into training because results are difficult.

The earlier engineering confirmation target is four fresh voices with two from
each existing female/male source category. This pilot does not automatically
fulfil that target. Preserve the representation commitment in the declaration;
use only voluntarily provided, approved metadata rather than inferring gender
from sound. If required representation is unavailable, record the gap and plan
additional recruitment; do not silently change categories or claim success.

Development results may inform a new model declaration. Freeze the checkpoint,
feature version, policy, renderer, decoder and verifier before opening the
confirmation recordings. Repeated tuning after confirmation access makes that
cohort development evidence; it must not remain labelled untouched final data.

## 5. Consent, storage and participant information

Use the institution/supervisor-approved participant-information and consent
process. The applicable institutional policy, authorisation, researcher contact,
approved storage location, access list, retention/deletion date and withdrawal
procedure are currently unconfirmed. Fill them before collection; this draft
is not ethics approval or a claim that recruitment can start immediately.

Explain the task, recording, two-reviewer access, optional nature, ability to
skip/stop, storage and planned use in plain language. Record distinct choices
for study evaluation, future model training, presentation playback and wider
sharing. Default optional uses to not permitted until consent is recorded.
No public demo or external AI upload follows from agreeing to local evaluation.

Keep consent/contact records separate from pseudonymous audio and ratings, with
restricted access. Pseudonyms do not make a recognizable voice anonymous.
State an actual withdrawal deadline/procedure and any limitations before consent.
For any future training use, define how affected derived files/checkpoints would
be quarantined or retrained; deleting a raw file alone does not erase a trained
model's contribution. No participant model training occurs in this pilot.

The [UK Data Service's recording-consent guidance](https://ukdataservice.ac.uk/app/uploads/specialconsiderationswhengainingconsent.pdf)
supports treating identifiable recordings and onward sharing explicitly. It is
a research-planning reference, not a statement that UK law or that service's
institutional procedures govern this project.

## 6. Annotation and use of the evidence

Store independent reviewer records, participant-intent notes, technical status,
source hash, consent scope, split and reference provenance separately. Reviewers
may identify acceptable/uncertain regions and intended variation; their ratings
alone do not create a cent-accurate ground-truth contour.

For guided numerical evaluation, independently establish intended register,
alignment and reference suitability. Keep unresolved cases unscoreable. For
free ideas without a pitch reference, report preservation, audible artifacts,
participant preference, technical acceptance and withholds—not invented pitch
accuracy. Any controlled +/−20/30c derivative is labelled synthetic intervention,
not an observed natural singing error or another person.

Use the same frozen melody extractor for any before/after evaluation, with
independent references and matched settings. BPDR only supplies accepted audio,
time mapping and preparation diagnostics. Final notes/durations, tempo/key,
genre and harmony remain other members' responsibility. Reference stimuli and
annotations are evaluation resources, not new BPDR musical-interpretation features.

Report participant-level results and denominators, both reviewer opinions,
disagreements, missing references, exclusions, withholds and failed audits.
Frames, trials, shifts, repeats and training seeds are not additional people.
Keep preference/no-harm judgments separate from numerical pitch, delivered-WAV
benefit, coverage and downstream extractor outcomes. With eight adults, results
are a small feasibility pilot; broad usable-accuracy claims need stronger evidence.

## 7. Operational sequence

1. Owner/supervisor review this protocol and fill the unresolved administration
   details. Confirm two reviewers and approve the guide stimuli.
2. Prepare the source-suitability and blinded37-trial packet; verify its hashes
   and blinding before assigning it. No reviews are claimed until completed.
3. Collect source reviews independently and record both decisions. Use findings
   to refine a newly declared training/reference set without changing old results.
4. Obtain pilot consent, allocate4/4 roles from metadata, then collect the48
   planned phrase slots with attempt/retry accounting.
5. Review development material, improve the model under declared experiments,
   and freeze a qualified pipeline. Preserve all existing technical limits.
6. Open confirmation once, complete independent listening and agreed numerical
   evaluation, and report failures alongside any benefit. Do not activate from
   a raw model score, a user checkbox or this plan alone.

## Confirmed benchmark coverage limitation,1 November

The existing frozen pack attempts20 cases for each singer. The female7 source
group has only4 scoreable cases. Even if all4 were verified improvements, its
all-attempt coverage would be4/20=20%, below the declared25% criterion (at least
5 successes). This is a reference-availability limitation, not a Transformer
accuracy measurement. Male2 and male4 have no scoreable cases and remain
unassessed. Additional fitting alone cannot make the current pack establish
that all represented groups pass practical usability.

Retain every old attempt, exclusion, group and threshold for engineering
comparison. The planned reference-suitability review and prospectively separated
pilot address missing evidence; they must not retroactively rewrite this pack,
quietly discard a difficult voice, or count repeated variants as independent
participants. A future evaluation cohort needs its own source/readiness audit,
prospective lock and unchanged reporting of failed/unsupported recordings.
The count calculation is retained in the render diagnosis's
`reference_coverage_feasibility.json`, bound to the actual pack and gate source.
